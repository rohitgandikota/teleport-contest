# SetVoice source and pinned build

The parent recording binary SHA256 ba4dbc1c823f8d4b0cfb6fd594d00ff0ff5754daaaa2036bee15baeffdf85aa7 matches the installed binary inspected read-only. sound-build-evidence.json pins its bytes, minimal macOS TTY hints, generated Makefile, configuration and object/source files. No build or C program ran. otool reads the existing binary: set_voice and sound_speak only save arguments to their stack and return, with no global access/call; monflee has no call to set_voice. Thus these speech operations have no effect in this exact recorder binary. This conclusion is independent of which branch the five recordings reached.

C sndprocs.h193-285 enables SetVoice only when an integrated sound backend is configured. Otherwise SetVoice and SoundSpeak are empty macros, and SND_SPEECH is undefined. The pinned minimal hints/Makefile enable the TTY windowport without a sound backend. Even with an integrated backend, sounds.c2161-2182 set_voice has a body only under SND_SPEECH.

In a speech-enabled build, set_voice is speech-context bookkeeping, not simply an audio call. It frees voice.nameid, stores gender, serialno (monster ID or special fallback), tone, volume, moreinfo, clears nameid, and ORs gp.pline_flags with PLINE_SPEECH. struct sound_voice also contains mon, but this owner does not assign it. JS has no voice object or these context updates. JS defines PLINE_SPEECH but does not implement its producer/consumer/clear lifecycle. Existing PLINE_VERBALIZE behavior is separate and remains implemented.

The direct consumers are sound_speak, which removes quote delimiters for PLINE_VERBALIZE then invokes soundprocs.sound_verbal if enabled, and the message/prompt paths. putmesg calls SoundSpeak after putstr; vpline clears PLINE_SPEECH at pline_done; yn_function's speech guard speaks the prompt and clears the flag before input. Those speech hooks/context are absent in JS. They are absent from this recorder's active build too. The source code has no RNG, time, position or gameplay-state mutation in set_voice. Do not infer that every possible sound backend is audio-only or that a speech-enabled build needs no port.
