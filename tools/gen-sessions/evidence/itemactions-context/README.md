# Inventory action context

Choosing the inventory action for identified oil now lights or snuffs the
potion. The menu already displayed that action, but the command queue treated
every potion as a dipping target. The tin menu also places the tin-opener
phrase before “and eat the contents,” matching C.

Eight inputs were fixed before the candidate. C confirms every prediction.
The complete native comparison improves from five to eight matching cases,
repairing three screen boundaries. All five negative reports are unchanged.
The recording contains 271 keys, 279 boundaries, 17,704 random calls and no
animation frames. It was recorded once from the pinned C build.

```sh
node tools/itemactions-context-input-gate.mjs
```

The gate validates the C recording and original inputs, then runs each case
with passive observation, ordinary input and deferred input. All five output
streams must agree. It checks the oil state and visible result, the tin menu
text, and 25 unchanged negative stream hashes. By default it writes nothing.
An optional new report path saves a compact result.

The controls cover unidentified oil, water, an oil lamp, a tin without an
opener and an opener that is carried but not wielded. Other inventory actions
and the transitive burning, eating and equipment implementations are not
established as complete by these cases. Native comparison checks decoded
styled cells, cursors, ordered random calls and animation frames; it is not
literal serialized-byte proof or a new held-out result.
